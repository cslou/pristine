Why this research

Does the pain pristine is trying to solve actually exist in the wild?

Spec-005 proposes narrowing pristine's memory system to developer use — paralleling spec-004's privacy→secrets pivot. Before committing to that direction, we need evidence: what do real developers complain about? What have they already tried? What do they wish existed?

The question isn't "is memory a problem." Every vendor says it is. The question is: what specific failures have developers actually hit, and what specific fixes do they ask for?

Scope

Claude Code, Cursor, Windsurf, Copilot, Aider, Continue.dev. Real usage, not vendor marketing. Pain + workarounds + product requests. Evidence with URLs.

The meta-finding

"Memory" is the wrong word

Developers don't ask for memory. They ask for three specific verbs — each with a distinct user experience and product affordance.

Continuity
"Where was I?"
Cross-session resumption. The most named pain. See Q1.2, Q6.
Enforcement
"Stop forgetting my rules."
Agent ignoring stated conventions. "Memory is a suggestion; hooks are enforcement." See Q1.3, Q1.4.
Recovery
"Survive compaction."
Session-middle context loss. Pre-compact hooks. See Q1.1, Q4.4.
What this means for pristine

Lead with a verb, not with "memory." "Never lose your place" lands. "Long-term memory" is vague. Different verbs imply different primary hooks, different UX, different evaluation targets.

Handoff docs are already ubiquitous. Devs will adopt a system that automates what they already do manually. The feature should probably be called "handoff" or "resume note," not "memory."

WorkaroundFrequent

Hook-based DIY is the power-user norm

Hooks read from the filesystem on every prompt. The filesystem survives compactions. So state saved to ~/.claude/persistent-memory/ is always available — no matter how many times the context compacts. This is the same pattern I use for 700+ hour sessions: critical state goes to disk via PostToolUse, gets re-injected via UserPromptSubmit.
yurukusa · GitHub issue #34556 · 2026 · link
The PreCompact hook does not ask the model to generate a summary. It captures the raw conversation to the database before compaction fires. No summary generation, no degraded context quality, just a straight write of everything to SQLite.
mikeadolan · claude-brain, GitHub issue #34556 · 2026 · link

VentureBeat coverage of March 2026 leak · link
Implication for pristine

Shell hooks (SessionStart, PostToolUse, PreCompact, UserPromptSubmit) are the accepted integration surface. Anything pristine ships should plug into these — don't invent a new surface. The emergent best practice: store raw at PreCompact, summarize later under clean context.

Anti-patternHigh-quality single-source

Memory content becomes classification cues

The most subtle failure mode in the whole corpus — from a developer running 700+ hours of Claude Code.

Today I discovered a subtle failure mode: if you write 'WatchDog' or 'idle hook' in memory/lessons files, the model uses those labels to classify incoming messages as 'automated' and deprioritizes them. Memory content becomes classification cues. I had to scrub all source-identification language from my memory files.
yurukusa · GitHub issue #34556 · link
Implication for pristine

Memories aren't neutral artifacts — they reshape the model's interpretation of future inputs. This is a second-order effect almost nobody has named publicly. An over-active memory system is essentially a correctness leak, not just an efficiency leak. Tagging + evaluating memory content for classification risk is a product consideration.

Build-vs-buy tilts heavily toward build

GitHub issue #34556 alone lists 15+ hand-built memory solutions — each rolled by a developer who tried products and wasn't satisfied:

Differentiator 1

Fully local + SQLite + markdown-editable (melchizedek, claude-brain)

Differentiator 2

Deterministic / derived-from-code rather than LLM-extracted (Aider RepoMap)

For pristine

Both differentiators are architecturally aligned with pristine. Local + single-file + plain-markdown editable is exactly our positioning. Derive-from-code is an under-explored layer we could add.

Cross-cutting observation

Extraction quality is the entire product

Hallucinated memories, remembering failures, classification cues, project scope bleed — all share one root cause: the memory was stored imperfectly. Every successful DIY tool mentions extraction quality explicitly.

The in-context agent writes far better summaries than any post-hoc extraction… this is why systems that compress transcripts after the fact tend to produce hallucinated memories — the summarizer wasn't there when it happened.
hatawong · GitHub issue #27298 · link
Single most actionable insight in the corpus

The model that did the work knows best what's worth remembering. Let the in-session agent write the summary before compaction wipes context, rather than asking a post-hoc model to reconstruct it from a shrunken context window. This aligns with the "store raw at PreCompact, summarize later under clean context" pattern.

Pristine's position

Pristine already has most of these primitives in the existing architecture. Spec-005's Scenario A ("resuming after a break") is the scenario developers ask for most. Narrowing the user scope to developers doesn't require new foundations — it requires refocusing.

Conclusion

What this means for spec-005

1. Dev-scope pivot is validated. The evidence says the pain is real, the workarounds are ubiquitous, and the existing products underdeliver on extraction quality. The pivot mirroring spec-004's privacy→secrets narrowing is supported.
2. Three-layer architecture is aligned. Slim always-loaded index + on-demand topic files + per-session summaries matches what developers build and what Anthropic apparently does internally.
3. PreCompact + SessionStart are the de-facto hooks. Non-negotiable. Any pristine-for-devs feature that doesn't plug into these won't be adopted.
4. Extraction quality is the moat. claude-mem has 58k stars despite hallucinated memories. If pristine beats extraction quality, it can beat the incumbent. "In-context summary at PreCompact" is the design pattern.
5. Local + markdown-editable + single-file is a differentiator, not a niche. Cursor's privacy-mode incompatibility and claude-mem's Chroma subprocess pain are both expressions of the same anti-pattern. Pristine's architecture already wins here.
6. Eval target shifts. LOCOMO tests personal-life recall. What should be measured: cross-session resumption accuracy, rule-adherence retention under long sessions, and hallucinated-memory rate. These are the product-shaped metrics.

The research didn't overturn spec-005's direction — it sharpened it. The pivot is not speculative; the product spec is nearly dictated by what developers are already building themselves.
