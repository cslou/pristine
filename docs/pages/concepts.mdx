# Concepts

## Local-first SDK

Pristine runs in your application process. It uses local storage and local embedding configuration by default, so the SDK does not require a hosted Pristine service.

The default local embedder may download model files on first use unless you pre-cache or configure the runtime for offline operation.

## Source-owned memory

Pristine memory is not a replacement for the original source. A stored chunk keeps source metadata such as kind, URI, entry ID, line number, timestamp, and custom metadata when provided.

A recall result should be treated as a pointer to likely relevant source context. Applications and agents can then inspect the authoritative file, transcript, message, or record.

## Project scoping

Memory methods require a `projectId`. This keeps unrelated workspaces from sharing search results when they use the same local database.

## Embeddings and SQLite

Pristine stores source metadata and vectors in SQLite-backed tables. Semantic recall embeds the query locally and searches within the selected project.

## Privacy and memory are separate primitives

Memory methods (`store`, `recall`, `forget`) manage source-owned chunks. Privacy methods (`secureAndRedact`, `reveal`, `scrubOutput`) manage sensitive text handling. Use them together when an application needs both memory and privacy boundaries.
