# Configuration

Pristine configuration controls local storage, user isolation, and embedding behavior. Use this Reference page alongside the [Memory](/memory), [Privacy](/privacy), and [Pi-dev integration](/pi-dev) guides.

## Default local setup

```ts
import { Pristine } from '@pristine/sdk';

const pristine = await Pristine.create();
```

The default setup initializes local paths for database and keys.

## Local paths

Use `baseDir` or `keysDir` when your application needs explicit storage locations. Keep those paths on the local device when preserving the default privacy model matters; see [Privacy](/privacy) for local database, key backup, and network wrapper responsibilities.

## Injected database or embedder

Advanced applications and tests can inject a `better-sqlite3` database or a custom embedder. If you inject an embedder, its vector dimension must match the vector storage initialized for the database.

## Project IDs

Pass a stable `projectId` to `store`, `recall`, and `forget`. A project ID is the boundary for memory search and deletion; see [Memory](/memory) for project scoping guidance.

## Offline operation

If the default local embedder is used, prepare model cache behavior before production or offline use. Pre-cache model assets when first-use downloads are not acceptable. Harness setup examples live under [Integrations](/pi-dev) and [Examples](/examples).
