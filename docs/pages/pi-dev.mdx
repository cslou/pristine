# Pi-dev integration

Pristine includes reference Pi-dev integrations for input-only privacy protection, indexing Pi JSONL session history, and recalling relevant source references. The detailed runbook lives at [`examples/pi-dev/README.md`](https://github.com/getlou-gh/pristine/tree/HEAD/examples/pi-dev).

## Prerequisite

Use this page when you run Pi from a local repository and can install project-local `.pi/extensions/*` and `.pi/skills/*` artifacts. Pristine stays local; Pi JSONL remains the source of truth.

## Privacy input reference

The `privacy-input` extension is an input hook reference that composes `detect`, `classify`, and `redact` before user text reaches model context. Classifier prompts receive sanitized context, `[CANDIDATE:<id>]` markers, non-value-derived candidate IDs, safe `sourceSpan` metadata, and safe `hint` metadata only — never raw candidates.

`uncertainPolicy` defaults to `block`; `redact` stores uncertain candidates with detector hints or fallback metadata; `allow` is an explicit unsafe opt-in excluded from the default no-raw-secret guarantee. This v1 is input-only: future tool-call reveal and future tool-result scrub hooks are not implemented.

## What Pi enforces vs. what Pristine recalls

Pi and the surrounding harness are responsible for deterministic policy: hooks, command guards, required checks, approval flows, and workflow enforcement. Those mechanisms reduce agent non-determinism when behavior must be reliable.

Pristine handles recall. In this Pi-dev example, Pi JSONL remains the source of truth. The Pristine-backed components index selected session content, retrieve ranked matches with source references, and route the agent back to source inspection before answering.

## Setup path

1. Read [`examples/pi-dev/README.md`](https://github.com/getlou-gh/pristine/tree/HEAD/examples/pi-dev).
2. Copy the reference artifacts into the target repo's `.pi/extensions`, `.pi/skills`, and `.pi/shared` layout.
3. Install extension dependencies as described in the runbook.
4. Start Pi from the target repo root so it discovers the local extensions and skill.

## Components

- `privacy-input` detects/classifies/redacts user input before model context.
- `jsonl-index` indexes Pi JSONL sessions into local Pristine storage.
- `pristine_recall` performs semantic discovery over indexed snippets.
- `search-session-history` inspects the authoritative JSONL source around returned references.

## Privacy input setup

For input privacy, copy/install `examples/pi-dev/extensions/privacy-input/` into `.pi/extensions/privacy-input/` and configure the host-wired detector, classifier callback, redactor, user ID, and local vault/key dependencies described in the runbook. Expected v1 outcome: user-pasted secrets are replaced with `[SENSITIVE:<type>:<id>]` placeholders or blocked before agent/model context. Tool-call reveal and tool-result scrub are future work.

## Expected outcome

After setup, Pi can answer memory/history questions by using `search-session-history`, calling `pristine_recall` when no exact source is known, and then inspecting the returned `sourceUri`, `entryId`, and line metadata in the source JSONL.

## Source inspection flow

1. Use `pristine_recall` when the target session or exact phrase is unknown.
2. Inspect returned `sourceUri`, `entryId`, and line metadata with `search-session-history` or ordinary file tools.
3. Treat JSONL as the source of truth; treat recall results as source references.

## Smoke check

Run the end-to-end TUI verification and privacy-input smoke checks in [`examples/pi-dev/README.md`](https://github.com/getlou-gh/pristine/tree/HEAD/examples/pi-dev). Privacy-input pass condition: a fake API key is blocked or transformed before model context; memory pass condition: the agent uses `search-session-history`, gets a relevant `pristine_recall` source reference, answers from the source JSONL, and avoids broad session greps after it has a usable reference.
