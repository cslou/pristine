# Pi-dev integration

Pristine includes a reference Pi-dev integration for indexing Pi JSONL session history and recalling relevant source references. The detailed runbook lives at [`examples/pi-dev/README.md`](https://github.com/getlou-gh/pristine/tree/HEAD/examples/pi-dev).

## Prerequisite

Use this page when you run Pi from a local repository and can install project-local `.pi/extensions/*` and `.pi/skills/*` artifacts. Pristine stays local; Pi JSONL remains the source of truth.

## What Pi enforces vs. what Pristine recalls

Pi and the surrounding harness are responsible for deterministic policy: hooks, command guards, required checks, approval flows, and workflow enforcement. Those mechanisms reduce agent non-determinism when behavior must be reliable.

Pristine handles recall. In this Pi-dev example, Pi JSONL remains the source of truth. The Pristine-backed components index selected session content, retrieve ranked matches with source references, and route the agent back to source inspection before answering.

## Setup path

1. Read [`examples/pi-dev/README.md`](https://github.com/getlou-gh/pristine/tree/HEAD/examples/pi-dev).
2. Copy the reference artifacts into the target repo's `.pi/extensions`, `.pi/skills`, and `.pi/shared` layout.
3. Install extension dependencies as described in the runbook.
4. Start Pi from the target repo root so it discovers the local extensions and skill.

## Components

- `jsonl-index` indexes Pi JSONL sessions into local Pristine storage.
- `pristine_recall` performs semantic discovery over indexed snippets.
- `search-session-history` inspects the authoritative JSONL source around returned references.

## Privacy prompt setup

For privacy boundaries, copy the privacy prompt from the [quickstart](/quickstart#privacy-setup-prompt). Expected outcome: sensitive text is redacted before agent/model context, local reveal remains privileged, and generated output is scrubbed before crossing the configured boundary.

## Expected outcome

After setup, Pi can answer memory/history questions by using `search-session-history`, calling `pristine_recall` when no exact source is known, and then inspecting the returned `sourceUri`, `entryId`, and line metadata in the source JSONL.

## Source inspection flow

1. Use `pristine_recall` when the target session or exact phrase is unknown.
2. Inspect returned `sourceUri`, `entryId`, and line metadata with `search-session-history` or ordinary file tools.
3. Treat JSONL as the source of truth; treat recall results as source references.

## Smoke check

Run the end-to-end TUI verification in [`examples/pi-dev/README.md`](https://github.com/getlou-gh/pristine/tree/HEAD/examples/pi-dev). Pass condition: the agent uses `search-session-history`, gets a relevant `pristine_recall` source reference, answers from the source JSONL, and avoids broad session greps after it has a usable reference.
