# Detect, classify, redact, reveal

Use Pristine privacy primitives to keep secrets out of agent/model context and session history while still allowing trusted local execution to use original values when needed.

## detect → classify → redact

The primitive-first flow separates local candidate discovery, caller-owned classification policy, and vault-backed redaction:

1. `detect` produces candidate IDs, `sourceSpan`s, detector metadata, and safe `hint` fields without returning raw candidate values.
2. `classify` presents sanitized context with `[CANDIDATE:<id>]` markers and safe `hint` metadata to caller-owned `classifierCallback` policy, which returns `secret`, `not_secret`, or `uncertain` decisions. Raw candidates are not sent to classifiers.
3. The harness policy maps `secret` decisions to confirmed `{ sourceSpan, type, label }` inputs. It also decides whether `uncertain` should block, ask a user, redact conservatively, or pass through.
4. `redact` stores only confirmed spans locally and returns model-safe text with `sensitiveRef` placeholders plus original `sourceSpan` and output `redactedSpan` metadata.

The SDK owns safe local contracts and vault-backed storage; the harness owns classification policy. The SDK does not implement a hosted classifier or bundled LLM classifier. Deterministic regex-only behavior can be a local classifier callback; it is not a privileged replacement for harness policy.

```ts
import { classify, detect, redact } from '@pristine/sdk';

const detected = detect(inputText, { sourceSurface: { kind: 'user_message' } });
const classified = await classify(inputText, detected.candidates, classifierCallback, {
  sourceSurface: detected.sourceSurface,
});
const confirmed = classified.decisions
  .filter((decision) => decision.verdict === 'secret')
  .map((decision) => ({
    candidateId: decision.candidateId,
    sourceSpan: decision.sourceSpan,
    type: decision.type,
    label: decision.label,
  }));
const redacted = await redact(inputText, confirmed, userId, {
  vaultStore,
  keyManager,
  kekManager,
});
```

Migrate new integrations to primitive-first `detect` → `classify` → `redact` so the harness explicitly owns policy and raw secret handling instead of relying on a composed SDK policy wrapper.

## reveal

`reveal` restores placeholders when the caller has local access to the vault and keys. Use it inside trusted local tool runners that need originals to execute, not as text that is sent back to the model by default.

```ts
const revealed = await pristine.reveal(modelSafeText, 'local-user');
```

## scrubOutput

`scrubOutput` scans text before tool results or generated output are written back into agent/model context or session history. Use it as a final safety check after local tools run or after generated text may have reintroduced sensitive values.

```ts
const toolResult = 'Sent the invoice email to ada@example.com.';
const scrubbed = pristine.scrubOutput(toolResult, ['ada@example.com']);
```

## manage sensitive refs

The management APIs operate on metadata by default: `listSensitive` and `getSensitive` return refs, generated labels, optional aliases, sensitivity types, and timestamps, but never plaintext secret values. `updateSensitive` only changes caller-provided visible metadata such as `alias`; aliases are returned by metadata APIs, so do not store secret plaintext in them. `deleteSensitive` removes exact refs. Use `resolveSensitive` only inside privileged local flows that are allowed to recover one ref's plaintext value.

```ts
const summaries = await pristine.listSensitive('local-user', { limit: 25 });
const first = summaries[0];

if (first) {
  await pristine.updateSensitive('local-user', first.sensitiveRef, {
    alias: 'primary contact email',
  });
}
```
