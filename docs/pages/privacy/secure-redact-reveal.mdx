# Secure, redact, reveal

Use Pristine privacy APIs to keep secrets out of agent/model context and session history while still allowing trusted local execution to use the original values when needed.

## secureAndRedact

`secureAndRedact` detects sensitive values, stores encrypted originals in the local vault, and returns redacted text with placeholders. Call it before text is sent to an agent or model so third-party LLM providers receive placeholders instead of original secrets.

```ts
const secured = await pristine.secureAndRedact(
  'Email Ada at ada@example.com about the invoice.',
  'local-user',
);

const modelSafeText = secured.redactedText;
```

## reveal

`reveal` restores placeholders when the caller has local access to the vault and keys. Use it inside trusted local tool runners that need originals to execute, not as text that is sent back to the model by default.

```ts
const revealed = await pristine.reveal(modelSafeText, 'local-user');
```

## scrubOutput

`scrubOutput` scans text before tool results or generated output are written back into agent/model context or session history. Use it as a final safety check after local tools run or after generated text may have reintroduced sensitive values.

```ts
const toolResult = 'Sent the invoice email to ada@example.com.';
const scrubbed = pristine.scrubOutput(toolResult, ['ada@example.com']);
```

## manage sensitive refs

The management APIs operate on metadata by default: `listSensitive` and `getSensitive` return refs, generated labels, optional aliases, sensitivity types, and timestamps, but never plaintext secret values. `updateSensitive` only changes caller-provided visible metadata such as `alias`; aliases are returned by metadata APIs, so do not store secret plaintext in them. Use `resolveSensitive` only inside privileged local flows that are allowed to recover one ref's plaintext value.

```ts
const summaries = await pristine.listSensitive('local-user', { limit: 25 });
const first = summaries[0];

if (first) {
  await pristine.updateSensitive('local-user', first.sensitiveRef, {
    alias: 'primary contact email',
  });
}
```
