Sprint-014 Summary — Spec-005 Phase 2 Schema Extension

Provisions the corpus-storage primitives that Phase-3 (indexer, sprint-015) and Phase-4 (searcher, sprint-016) will consume. Pure additive DDL + new method surface; no user flows introduced.

Goal

Extend the existing ConversationStore schema (Sprint-009) with project scoping, oversize-chunk linkage, sliding-window + session vector indexes, summaries table + public views, plus mutator/reader methods. All changes are migration-safe and backward-compatible with Sprint-009-era databases.

Known spec §12 deviations (documented)

  • messages.id stays INTEGER AUTOINCREMENT (spec says TEXT UUID). Sprint-009 FTS5 content_rowid=rowid linkage requires INTEGER rowids. Follow-up GH issue #106.
  • conversations.started_at view-aliased from created_at with CAST(strftime('%s', created_at) * 1000 AS INTEGER). Physical column stays TEXT; the conversations_public view does the ms cast.
  • messages.turn_index view-aliased from sort_order in messages_public. Physical column unchanged.
  • messages.timestamp — same CAST pattern as started_at in messages_public.timestamp. Physical column stays TEXT + nullable (NULL passes through the view per documented contract).

Key changes — before / after

Additive migration. No columns renamed or dropped. Sprint-009 tables + FTS5 triggers preserved verbatim.

Columns added

TableColumnTypeDefault / Back-fill
conversationsproject_idTEXT NOT NULLDEFAULT 'default', back-fill: COALESCE(NULLIF(user_id,''), 'default')
messagesproject_idTEXT NOT NULLDEFAULT 'default', back-fill: COALESCE((parent.project_id), 'default') (orphan-safe)
messagesparent_message_idINTEGER NULLNULL (chunks not yet written)

New tables (all-relations.txt)

  • summaries(id TEXT PK, session_id TEXT NOT NULL, project_id TEXT NOT NULL, text TEXT NOT NULL, timestamp INTEGER NOT NULL, metadata TEXT) — scratch-pad for Phase-5 reference summaries. No FK to conversations (session lifetime is harness-scoped).
  • window_messages(conversation_id, window_index, message_id, position, PRIMARY KEY composite) + FK to messages(id) — join table for sliding-window membership.
  • vec_windows (vec0 virtual) — (conversation_id, window_index, embedding float[768]), sliding-window primary semantic index.
  • vec_sessions (vec0 virtual) — (conversation_id TEXT PK, embedding float[768], +updated_at INTEGER), whole-conversation secondary index.

Indexes added (indexes.txt)

ix_conversations_project_started  ON conversations(project_id, created_at DESC)     (§12)
ix_messages_conv_sort             ON messages(conversation_id, sort_order)          (§12)
ix_messages_timestamp_nonchunk    ON messages(timestamp DESC) WHERE parent_message_id IS NULL  (§12 partial)
ix_messages_parent                ON messages(parent_message_id)                    (§12)
ix_summaries_project_time         ON summaries(project_id, timestamp DESC)          (§12)
ix_window_messages_message_id     ON window_messages(message_id)                    (Phase-4 reverse joins, spec-gap fill)

Views added (messages_public / conversations_public / summaries_public)

  • messages_public(id, conversation_id, turn_index, role, content, timestamp, project_id) — excludes parent_message_id; timestamp cast to unix-ms; declared-order pinned.
  • conversations_public(id, project_id, started_at) — excludes user_id, content_hash, message_count; created_at → started_at unix-ms.
  • summaries_public(id, session_id, project_id, text, timestamp) — excludes metadata.

New typed errors

  • ConversationNotFoundError — thrown by addMessage when the parent conversation row doesn't exist.
  • InvalidArgumentError — thrown by addSummary on empty text and by getRecentSummaries on limit <= 0.

New API surface on ConversationStore

  • addMessage(conversationId, { role, content, timestamp?, parentMessageId? }) — void return per spec §5.1.1. Atomic MAX(sort_order)+1 + INSERT + message_count++ in a single db.transaction. project_id read from parent conversation.
  • addSummary({ sessionId, projectId, text, timestamp, metadata? }) — returns UUID. Empty-text rejection.
  • getRecentSummaries(projectId, limit = 10) — DESC order via ix_summaries_project_time. limit > 0 guard.

Migration engine (new)

PRAGMA user_version-gated, atomic db.transaction wrapping all versioned steps. Fresh v0 DBs run all 4 story blocks in one transaction; partway-migrated DBs pick up only the steps they're missing. Idempotent on re-run.

PRAGMA foreign_keys = ON is now applied on every ConversationStore construction — Sprint-009 declared the FK but didn't enable the pragma; this sprint closes that gap so window_messages's FK to messages(id) is enforced.

Known spec §12 deviations (callout per sprint AC)

  • messages.id stays INTEGER AUTOINCREMENT (spec says TEXT UUID) — Sprint-009 FTS5 content_rowid=rowid requires INTEGER. Tracked as #106.
  • conversations.started_at is view-aliased from physical created_at via CAST to unix ms in conversations_public (spec §12 types it INTEGER).
  • messages.turn_index view-aliased from physical sort_order in messages_public.
  • messages.timestamp view-aliased with same CAST pattern; NULL passes through (physical column nullable TEXT) — pinned by regression test.
  • messages.metadata — sprint doc AC over-specified; physical schema never gained the column. addMessage signature does not accept metadata. If needed, a follow-up story can add the column + extend the signature.

Negative assertions pin the excluded internal columns: messages_public never exposes parent_message_id; conversations_public never exposes user_id, content_hash, message_count; summaries_public never exposes metadata.

SELECT id, session_id, project_id, text, timestamp, metadata
FROM summaries
WHERE project_id = ?
ORDER BY timestamp DESC
LIMIT ?

→ SEARCH summaries USING INDEX ix_summaries_project_time (project_id=?)

Indexed seek + scan — no full-table-scan + sort. Test runs this query plan against a 50-row seed to keep the optimizer reliably in index-use territory.
