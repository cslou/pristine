FlowVerified by

Affected (existing)

Now dispatches by task_type: embed-message calls the injected handler (Story 6); legacy extract-conversation falls through to the orchestrator path (still throws under spec-005's orchestrator: null, but the throw is now CAUGHT inside the try-catch and converted to per-task markFailed — the worker keeps draining other tasks).
storeAsync (in src/client.ts): explicitly UNCHANGED per the Sprint-Level Technical Context. Still routes through legacy IngestQueue.enqueue (creates extract-conversation tasks). Wiring it to indexer.ingest is sprint-016's first move. Documented in PR #122 + sprint doc.

Crash-recovery contract (verified)

1. claimNext sets status='processing', started_at=now
2. worker crashes / fails to call markCompleted
3. claimNext (next call) flips rows older than 30s back to 'pending'
4. processNext re-claims, dispatches, completes
   → orphan ends in 'completed', no double-write to vec_windows
     (upsertWindow's DELETE+INSERT is idempotent)

Inline simulation in tests/memory/indexer/embed-worker.test.ts and tests/integration/indexer.test.ts. Real-process-kill is out of scope (subprocess + in-memory DB don't share state).

Vec_windows write idiom (verified contract)

BEGIN;
  DELETE FROM vec_windows WHERE conversation_id = ? AND window_index = ?;
  DELETE FROM window_messages WHERE conversation_id = ? AND window_index = ?;
  INSERT INTO vec_windows(conversation_id, window_index, embedding) VALUES (?, ?, ?);
  -- one INSERT INTO window_messages per constituent message_id with explicit position
COMMIT;

vec0 does not support INSERT OR REPLACE on (conversation_id, window_index). DELETE+INSERT idiom pinned by sprint-014 Story 2 PK-rejection test; reused by sprint-015 Story 3's upsertWindow + Story 5's buildSessionVector.

Documented sprint-016 follow-ups

  • Wire storeAsync to indexer.ingest — src/client.ts stays untouched in sprint-015 per the Sprint-Level Technical Context. storeAsync still calls the legacy IngestQueue.enqueue (creates extract-conversation tasks that no longer process). Sprint-016's first move.
  • Oversize-parent window-bloat — surfaced by Story 7's oversize integration test. When a turn is split into parent + chunks, the parent row stores the full ~13K-char content at its own sort_order. The window-assembler queries messages by sort_order range, so a window spanning the parent's slot pulls the full content into the embed text — would overflow Nomic v1.5's 8192-token context in production. Stub embedder hides this in the test. Architectural fix needs window assembly to skip parents-with-children (or a separate sort-order space for parents).
  • Auto-build session vectors — Story 5's buildSessionVector is currently invoked only on explicit consumer demand. Auto-build-on-ingest hooks land in sprint-016 once retrieval pressure is real and the cost/benefit is concrete.
  • UUID migration for messages.id — GH #106 still open. Spec-005 §13 sketches TEXT UUID; shipped schema is INTEGER PRIMARY KEY AUTOINCREMENT (preserves sprint-009 FTS5 content_rowid=rowid linkage). All Phase-3 writes use INTEGER throughout.
  • Convention follow-up — multiple P2s across stories flagged the types-in-core convention deviation (CLAUDE.md says module contracts live in src/core/interfaces.ts; the codebase keeps types local to their owning modules per existing pattern). Uniform refactor when convenient.
